# Nexora Audio Player — Architecture

> Companion to the upstream Nexora backend (`suryaprakash251201/nexora`). This repo
> contains **only** the mobile client (Android + iOS). The backend is consumed via
> its existing HTTP API and is never modified here.

## Why this repo exists separately

The upstream monorepo (`nexora`) ships a generic file-manager mobile app under
`mobile/`. We are building a **dedicated audiophile-grade music client** that
shares the same backend but is a separate product surface — different screens,
different state machines, different audio engine capabilities (real DSP, real
analyzer, real waveform). The original `mobile/` directory stays untouched.

This document is the contract between the brief and the code.

## Hard constraints we do not violate

| Constraint | Source | Enforcement |
|---|---|---|
| Never fabricate analyzer values | brief + own policy | All DSP/FFT code is wired to real PCM via `react-native-audio-api`; UI displays `—` when source isn't available, never a guessed number. |
| Never claim "bit-perfect" without proof | brief | UI shows the actual chain: `RAW → DSP OFF → bit-perfect on supported paths`; lossy transcodes show "transcoded" badge. |
| Reuse existing backend | brief | No new backend endpoints are assumed. If we need one we propose it in `docs/SYNC.md` and gate the feature. |
| Reuse existing mobile app's primitives | brief | `expo-secure-store`, `expo-image`, expo-dev-client flow, theme tokens copied over. |
| Don't pretend per-instrument stereo data exists | brief | The Studio DSP "radial" visual is labelled "DSP-derived" whenever the position is synthesised. |

## Audio architecture (one-paragraph)

UI subscribes to a **PlaybackStore** (Zustand). The store never talks to audio
directly — it delegates to `AudioController`. The controller owns the
`react-native-track-player` singleton (so background + lock-screen behaviour
keeps working untouched) and a parallel `react-native-audio-api` source that
receives the same audio for analysis and DSP. On iOS the analyzer tap comes
from the same AVAudioEngine chain so EQ + analyzer share PCM. DSP state lives
in `DspStore` and is persisted to SQLite (no AsyncStorage). The unified library
is a `LibraryStore` with three source resolvers (`NexoraResolver`,
`DeviceResolver`, `OfflineResolver`) and a deduplication pass keyed on a
stable fingerprint (size + first 64 KB of audio SHA-256 when available, else
`rootId:path`).

## Connection to backend

The mobile client only talks to Nexora via:

1. `POST /auth/login` → `{user, token}` stored in `expo-secure-store`.
2. `GET /audio/info?root&path` → ffprobe result, cached client-side keyed by
   `{root, path, size, mtime}` exactly like the server.
3. `GET /files/raw?root&path` (HTTP Range) for streaming playback.
4. `GET /files/transcode?root&path&session&quality&format` for non-native
   codecs (ALAC/WMA/DSD/Opus/OGG/etc.), with stable per-playback `session`.
5. `GET /files/thumbnail?root&path&size` for embedded album-art (server-side
   extract).
6. `GET /audio/lyrics?root&path` + sibling `.lrc` upload/download.
7. `GET /playlists` and the four mutation endpoints for playlist sync.
8. `GET /favorites` and the two mutations for favorites sync.
9. `POST /recents` (via the `/favorites` handler's recents upsert) for play
   history batching.

`AudioEngine` never directly calls the server during playback — the stream URL
is resolved **before** `TrackPlayer.add()` and cached per `(rootId, path)`.
